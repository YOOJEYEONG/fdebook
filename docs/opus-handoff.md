전달 상태: 아직 전달되지 않음. 이 문서를 읽었다는 이유만으로 모델을 Opus 5.5라고 주장하지 말고, 세션의 실제 모델 표시를 확인한다.

## 책임과 시작 조건
Codex는 설계·계획 담당, 현재 탭 Opus는 조사·사실 검증·구현·QA 실행 담당이다. 다른 모델이나 다른 탭으로 임의 대체하지 않는다. 작업 디렉터리는 `/Users/yujeyeong/Desktop/FDE`이다. `docs/design.md`를 읽고 조사부터 시작한다. 제품 코드는 설계 검토 후 작성한다. 요청과 충돌하는 스킬의 불필요한 승인 절차는 추가하지 않는다.

## 역할과 순서
1. 채용 조사자: 설계의 자료 품질 기준에 맞춰 공식 공고와 직무 소개를 조사한다. `docs/research.md`에 원문 링크, 접근일, 지역, 상태, 요구 역량, 표본 한계를 기록한다. FDE가 일반 개발자보다 취업이 쉽다는 전제부터 검증한다.
2. 사실 검증자: 가능하면 별도 Opus 검토 컨텍스트를 사용한다. 불가능하면 같은 세션에서 검증 패스를 분리하고 독립 검증이라고 주장하지 않는다. 원문 재확인 후 `docs/verification.md`에 주장·근거·판정·수정 내역을 남긴다.
3. 교육 설계자: 검증된 요구 역량을 12주 기본 학습 경로와 과제·평가 기준에 매핑한다. 자료 읽기에서 끝내지 말고 고객 인터뷰 → 통합 → 운영 → 데모 → 성과 설명의 산출물을 만든다. 자료 부족에 맞춰 분량을 줄이고 내용을 꾸미지 않는다.
4. Rust 구현자: 아래 스킬을 읽고 설계의 단일 서버·SSR·로컬 진도 방식을 최소 코드로 구현한다. 특정 파일 배치는 직접 결정하되 Cargo.toml, src/main.rs, static/, content/, README.md 정도로 시작하고 불필요한 추상화는 만들지 않는다.
5. QA 담당자: 실제 실행·브라우저 확인 및 핵심 로직 검사를 수행하고 `docs/qa.md`에 명령·결과·남은 한계를 적는다. 검증자는 누락을 고친 뒤 재확인한다.
