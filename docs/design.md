# FDE 취업 학습 공간 — 설계 초안

상태: 사용자 검토용. Opus 세션 연결 전이며 자료조사·구현은 시작하지 않았다.

## 목표와 가정
개발 경험이 있는 한국어 사용자가 Forward Deployed Engineer로 전환하기 위해 역량 차이를 파악하고, 고객 문제 해결 실습을 수행하고, 면접에서 설명할 증거를 쌓는다. 취업 보장이나 FDE 채용 우위는 주장하지 않는다. 경력, 주당 학습 시간, 희망 지역은 미확인이다. 기본 제안은 주 10시간·12주이며 사용자가 변경할 수 있어야 한다.

## 접근 선택
- 문서형 자료집: 구현은 작지만 실습·지원 준비를 지속하기 어렵다.
- 개인 학습 대시보드(추천): 오늘 할 일, 실습 산출물, 진행률을 연결한다.
- 다중 사용자 LMS: 계정·운영 부담이 커서 초기 목적에 과하다.

위 선택은 설계자의 제안이며 사용자 확정 사항이 아니다.

## 화면과 흐름
1. 시작 설정: 경험·희망 지역·주당 시간을 입력하고 로컬에 저장한다.
2. 오늘의 학습: 현재 주차, 다음 과제, 예상 시간, 이어하기를 먼저 노출한다.
3. 역량 지도: 고객 요구 발견, API/데이터 통합, SQL/데이터 모델링, 배포·운영, AI 응용·평가, 의사소통을 실제 공고 근거에 연결한다.
4. 주차별 과정: 목표 → 출처 있는 설명 → 실습 → 제출할 산출물 → 완료 기준. 단순 링크 목록으로 끝내지 않는다.
5. 고객 프로젝트: 요구사항 인터뷰, 문제 정의서, 작동하는 PoC, 배포·장애 대응, 데모, 효과 측정까지 하나의 사례로 묶는다.
6. 면접·지원: 요구 발견 역할극, 통합 설계, 디버깅, 고객 데모, 행동 면접 문항과 평가 기준. 지원 현황은 회사·URL·상태·메모를 로컬에 기록한다.
7. 근거 자료: 회사·직무·지역·원문 URL·접근일·원문 요약·검증 상태. 만료 공고는 현재 채용과 구분한다.

PC는 왼쪽 내비게이션과 읽기 쉬운 본문, 모바일은 상단 메뉴와 한 열 구성. 한국어 가독성, 키보드 조작, 명확한 포커스, 충분한 명도 대비를 필수로 한다. 체크 여부와 실력 평가는 구분한다.

### 시각 설계 제안
고객 프로젝트 작업 노트처럼 현재 문제, 수행할 행동, 남길 증거를 한 화면에 연결한다. 첫 화면의 중심은 홍보 문구나 숫자가 아니라 오늘의 고객 과제다. 배경 `#F7F9FC`, 본문 `#182536`, 보조 글자 `#526276`, 강조 `#2457C5`, 성공 `#18704A`를 제안한다. 한국어는 시스템 고딕, 코드만 시스템 고정폭을 쓰고 외부 폰트 의존성을 추가하지 않는다. 본문은 왼쪽 정렬, 최대 72ch, 기본 16px/행간 1.7이다. 진행 순서에만 번호를 쓰고 장식 애니메이션은 생략한다. 이 항목은 설치한 frontend-design의 정보 위계·절제 원칙을 설계에 적용한 결과이며 실제 화면 검증은 Opus QA의 책임이다.

```text
학습 메뉴 | 오늘의 고객 문제와 다음 과제
          | 목표 → 실습 → 제출할 증거
          | 평가 기준 / 관련 채용 근거
```

## 커리큘럼 초안 — 조사 후 보정
- 1–2주: 직무 이해, 역량 진단, 고객 문제 정의·요구사항 인터뷰.
- 3–4주: HTTP/API·인증·웹훅·SQL·데이터 정제 및 통합.
- 5–6주: 배포·관측·실패 복구·보안·운영 제약.
- 7–8주: AI FDE를 목표로 할 경우 검색·도구 연동·평가·비용·지연. 일반 FDE 경로와 선택 분리.
- 9–10주: 고객 시나리오 기반 종합 프로젝트와 데모.
- 11–12주: 사례 문서·이력서·모의 면접·지원.

Rust는 이 웹앱 구현 제약이다. 실제 FDE 채용의 보편적 필수 언어라고 가르치지 않는다. 공고가 요구하는 Python·TypeScript 등을 임의로 제외하지 않는다.

## 기술 제안과 최소 범위
Rust 단일 애플리케이션이 HTML/CSS와 정적 자료를 제공한다. Axum 등 검증된 HTTP 라이브러리는 안전한 서버 구현을 위해 허용하되 버전·필요성은 구현자가 공식 문서로 확인한다. SSR 우선, 프런트엔드 프레임워크와 WASM은 도입하지 않는다. 소량의 브라우저 JavaScript로 로컬 저장과 진행률을 처리한다. 이는 Rust 서버와 브라우저 표준 기술 조합이라는 설계 제안이다.

학습 콘텐츠는 버전 관리되는 JSON, 개인 진도는 localStorage. 계정·외부 DB·유료 API·실시간 채용 크롤러는 초기 범위에 없다. 진도 내보내기/가져오기에서 버전과 스키마 검증, 잘못된 입력 시 기존 데이터 보존이 필요하다. 자료와 메모는 HTML로 실행하지 않는다. 서버는 기본 localhost 바인딩이다.

## 자료 품질 기준
Opus 조사자가 서로 다른 기업의 공식 직무 설명·공고를 목표 8개 이상 수집하되 국내 표본 부족은 그대로 보고한다. 한국/해외, 현행/과거, FDE/유사 직무를 구분한다. 모든 공고에 필수·우대 역량과 지역·언어·경력 조건을 남긴다. 취업 용이성 비교에는 비교 가능한 채용/지원자/채용률 자료가 필요하며 공고 몇 개만으로 결론 내리지 않는다.

사실 검증자는 조사자의 요약이 아니라 원문을 다시 열어 주장·출처 대응표를 작성한다. 확인 못 한 주장은 본문에서 제외하거나 미확인으로 표시한다. 학습 과제마다 목표 역량·산출물·평가 기준·근거를 연결한다.

## 완료 기준
처음 방문 → 학습 시작 → 과제 체크 → 새로고침 후 복원 → 진도 내보내기/가져오기 → 면접 준비의 흐름이 동작한다. 빈 자료, 잘못된 백업, 저장 불가 상황에 설명이 보인다. 375px/1280px에서 본문 넘침이 없고 키보드로 핵심 흐름을 수행할 수 있다. Rust fmt/check/test/clippy와 실제 브라우저 확인 결과를 기록한다. 검증하지 않은 항목은 완료로 표시하지 않는다.
