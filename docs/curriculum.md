# 커리큘럼 보정안 (역할: 교육 설계자)

- 수행: Opus 5.5, 조사·검증과 같은 세션. 근거는 `docs/verification.md`에서 "확인" 판정을 받은 항목만 사용한다. 근거 번호 `R#`은 `docs/research.md` 표본 번호, `V#`은 검증표 번호.
- 기본값: 주 10시간 × 12주. 사용자의 경력·희망 지역·주당 시간은 아직 미확인이므로 앱에서 변경 가능해야 한다.
- 이 과정은 취업을 보장하지 않는다. FDE가 일반 개발자보다 취업이 쉽다는 근거는 없다(V40).

## 설계 보정 원칙

1. **실습 언어는 Python 기본, TypeScript 보조.** 언어가 명시된 공고에서 Python이 가장 많다(V3, V18, V20, R2, R8). Rust는 이 웹앱의 구현 제약일 뿐이며 직무 역량으로 가르치지 않는다(V41).
2. **AI 적용 주차를 선택이 아닌 기본 경로로.** 상세 확인 9건 중 6건이 LLM/AI 적용을 필수 또는 경험으로 요구한다(R2, R3, R4, R6, R8, R9). 비AI 경로(데이터 파이프라인 중심, R1·R3 근거)는 대체 과제로 유지한다.
3. **모든 주차가 하나의 고객 사례에 산출물을 누적.** 고객 인터뷰 → 문제 정의 → 통합 → 운영 → 평가 → 데모 → 성과 설명.
4. **체크 완료 ≠ 역량 확보.** 각 과제의 완료 기준은 산출물 존재 + 자기 평가 루브릭 통과이며, 앱은 둘을 따로 표시한다.
5. **지원 조건 필터 학습.** 경력 연수, 출장 비율, 출근 빈도, 비밀취급인가 같은 비기술 조건을 1주차에 읽게 한다(V2, V6, V10, V11, V16, V22).

## 공통 사례

가상의 고객 "지역 물류 중소기업의 상담 문의 분류·응답 지연" 문제를 12주 동안 한 사례로 다룬다. 실제 기업·인물로 꾸미지 않는다. 데이터는 직접 만든 합성 데이터(CSV/JSON)를 쓴다.

## 평가 루브릭(공통 3단계)

- 미흡: 산출물 없음 또는 재현 불가.
- 충족: 완료 기준을 모두 만족.
- 증거 수준: 충족 + 타인이 README만으로 재현 가능하고 한계가 문서에 적힘.

## 후속 구현 적용 요점 (스킬)

### ponytail (`/Users/yujeyeong/.agents/skills/ponytail/SKILL.md`, full)
- 사다리 순서 적용: 필요성 → 기존 코드 → 표준 라이브러리 → 플랫폼 기능 → 설치된 의존성 → 최소 코드.
- 진도 저장은 `localStorage`, 체크는 `<input type="checkbox">`, 백업은 `Blob` 다운로드 + `<input type="file">`. 프레임워크·상태관리 라이브러리 금지.
- 서버는 Axum 하나 + 직렬화(serde/serde_json) + 정적 파일 제공 정도로 시작. 템플릿 엔진이 필요한지는 SSR 페이지 수 보고 결정.
- 생략 금지: 백업 가져오기 입력 검증(버전·스키마), 잘못된 입력 시 기존 데이터 보존, HTML 출력 이스케이프, 접근성 기본.
- 비단순 로직(진도 집계, 백업 검증, 이스케이프)마다 실행 가능한 검사 1개씩. 단순 한 줄은 테스트 생략.
- 의도적 단순화에는 `// ponytail:` 주석으로 한계와 확장 경로 기록.

### find-skills (`/Users/yujeyeong/.agents/skills/find-skills/SKILL.md`)
- 새 스킬 설치 전 기존 설치(`.agents/skills`, `.claude/skills`, `~/.agents/skills`) 먼저 확인. 현재 rust-best-practices, frontend-design 설치 확인됨.
- 검색 결과만으로 추천 금지: 설치 수(1K+ 선호), 출처 평판, 저장소 별 수 확인 후 필요한 것만 설치.
- 이번 범위에서 추가 설치 필요 없음.

### rust-best-practices (`.agents/skills/rust-best-practices/SKILL.md`)
- 함수 인자는 `&str`, `&[T]`. 불필요한 `.clone()` 금지.
- 프로덕션 경로에서 `unwrap()`/`expect()` 금지, `Result` + `?`. 바이너리이므로 `anyhow` 허용, 별도 오류 계층은 필요해질 때만.
- `cargo clippy --all-targets -- -D warnings` 통과. 허용이 필요하면 `#[expect(...)]` + 사유 주석.
- 테스트 이름은 동작 서술형(`import_should_keep_existing_progress_when_backup_invalid`), 테스트당 단언 1개 지향.
- 타입 상태·제네릭 디스패치 등 고급 패턴은 ponytail과 충돌하므로 도입하지 않음.

### frontend-design (`.agents/skills/frontend-design/SKILL.md`)
- 첫 화면 중심은 "오늘의 고객 과제". 큰 숫자 통계·그라디언트 히어로 금지.
- 번호 표기는 주차·단계처럼 실제 순서가 있는 곳에만.
- 피해야 할 기본값: 전부 대문자 라벨, 제목 위 장식 라벨, 한 단어만 강조, 동일 카드 반복·같은 그림자, `A · B · C` 메타 문자열, 링크 뒤 `→`.
- 본문 80자 미만(설계값 72ch), 반응형·키보드 포커스·reduced motion·명도 대비는 품질 바닥으로 처리.
- 문구는 사용자 관점 능동형: 버튼 "진도 내보내기" → 완료 알림 "진도를 내보냈습니다"처럼 같은 동사 유지. 오류는 원인과 해결법을 구체적으로.
- 설계 색상(`#F7F9FC` 배경 등)이 위 생성형 기본값 목록에 해당하지 않음을 확인. 실제 화면 확인은 QA 단계.

## 설계 수정 제안 (Codex/사용자 검토용)

1. `design.md` 커리큘럼 7–8주 "AI FDE 선택"을 **기본 경로 + 비AI 대체 과제**로 변경.
2. 학습 실습 언어를 Python 기본으로 명시. 콘텐츠 JSON 과제마다 `language` 필드.
3. 근거 자료 화면 필드 추가: 출처 유형(A/B/C), 출장 비율, 출근 빈도, 비밀취급인가·거주 조건, 상태 값에 "마감 표시 충돌".
4. 공고 증가 통계는 "수요 신호(2차 보도)"로만 표시하고 취업 용이성 문구 금지.
5. 11주차 사례 문서 형식을 채널코퍼레이션 지원서 요구(AI 문제 해결 경험, 현장 문제 발견 경험)에 맞춤.
6. 1주차에 사용자 경력·희망 지역 입력 후, 표본 중 지원 조건 충족 공고를 보여주는 단순 필터(경력 연수 기준). 실시간 크롤러는 여전히 범위 밖.
7. 한국 표본 보강 전까지 "국내 FDE 요구 역량" 일반화 문구 금지(국내 현행 원문 2건).
