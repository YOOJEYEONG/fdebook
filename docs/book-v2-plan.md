# FDE 기술 학습북 v2 설계 및 실행 계획

2026-11-17 사용자의 수정 요구가 기존 대시보드 설계에 우선한다. Exact는 Expo의 https://github.com/expo/exact 이다. Codex는 설계·계획 담당, Opus 5.5는 조사·집필·검증·Exact 구현·QA 담당이다.

## 제품의 중심
FDE에 필요한 직무 기술을 페이지 자체에서 배우는 한국어 온라인 교재. 사용자는 목차에서 한 절을 선택하고 본문을 읽고 예제를 실행한 뒤 연습문제와 해설로 이해를 확인한다. 일정 관리, 지원 현황, 체크리스트는 중심 기능에서 제외한다. 기존 기록은 지우지 않는다.

독자 기본값은 프로그래밍 기초를 아는 개발자이며 FDE 업무·데이터 통합·AI 운영은 처음인 사람이다. 용어는 첫 등장에 풀어 쓴다. 학습을 위해 외부 유료 API나 계정이 필수여서는 안 된다. 실제 네트워크 API가 필요한 심화 예제는 비용과 준비물을 명시하고 로컬 대안을 제공한다.

## 정보 구조와 읽기 UX
홈은 책 소개, 배울 기술, 선수지식, 전체 목차, 시작하기로 구성한다. 데스크톱에는 장별 목차, 읽기 본문, 현재 절의 소목차를 둔다. 모바일에는 접을 수 있는 목차와 단일 본문을 둔다. 각 절에 고유 URL, 이전/다음 절, 출처, 읽기 위치를 제공한다. 코드 블록에는 언어, 실행법, 예상 출력, 복사를 제공한다. 해설은 먼저 풀어 본 뒤 펼칠 수 있다. 코드 가로 스크롤은 블록 안으로 제한한다. 헤딩·링크·키보드 포커스·반응형과 한국어 가독성을 검증한다.

## 목차 초안 — 새 조사로 보정
1. FDE 업무와 엔지니어링 사고: 고객 현상과 문제 구분, 요구 발견, 성공 지표, 범위·수용 기준, PoC와 운영 제품.
2. HTTP와 API 통합: 요청·응답, JSON, 상태 코드, 인증·권한, 페이지네이션, 시간 제한, 재시도·백오프, 멱등성, 웹훅·서명.
3. 데이터와 SQL: 관계 모델, 키·조인, 트랜잭션, 정제·결측·중복, ETL, 품질 검사, 개인정보 최소화.
4. 제품 구현과 전달: 작은 백엔드, 인터페이스 계약, 오류 처리, 테스트, Docker, CI/CD, 환경 설정·비밀값, 배포·롤백.
5. 운영과 문제 해결: 로그·메트릭·트레이스, 재현과 가설 검증, 성능·지연·비용, 장애 대응, 보안·권한·위협 모델.
6. AI FDE: LLM 입출력, 구조화 출력, 도구 호출, 임베딩·검색·RAG, 평가셋·정확도/정밀도/재현율, 환각·프롬프트 인젝션, 비용·지연·모니터링. 일반 FDE와 AI 특화 역량을 구분한다.
7. 고객 커뮤니케이션과 설계 결정: 기술 설명, 데모, 트레이드오프, 아키텍처 결정 기록, 인수인계, 효과와 한계 보고.
8. 종합 예제: 합성 상담 문의 데이터를 받아 저장·분류·조회·평가하는 작은 시스템. 장별 기술을 연결하는 해설과 실행 안내.

## 절별 필수 구성과 품질 기준
각 절은 (1) 학습 목표·선수 개념 (2) 실제 FDE 상황 (3) 원리와 용어 설명 (4) 실행 가능한 작은 예제와 예상 결과 (5) 흔한 오류·디버깅 (6) 이해 확인 문제 2개 이상과 해설 (7) 공식 학습 출처 및 접근일을 포함한다. 단순 과제 지시나 링크 목록은 본문으로 인정하지 않는다. 개념에 맞지 않는 억지 코드 예제는 쓰지 않고 분석 사례·좋은/나쁜 예를 사용한다.

출처는 역할 설명에는 기업 공식 자료, 기술 설명에는 프로토콜 표준과 공식 문서를 우선한다. 공고 몇 개의 문구를 기술 사실의 근거로 쓰지 않는다. 근거를 열어 확인하고 주장·출처 대응표를 작성한다. 원문을 복제하지 않고 한국어로 새로 설명한다. 예제는 실제로 실행하여 출력과 일치시킨다. 실행하지 못한 예제는 검증 완료라고 표시하지 않는다.

## 구현 제약
Expo Exact의 공식 README, AGENTS.md, 웹사이트용 시작 가이드, 관련 공식 스킬을 읽고 현재 지원 API와 웹 빌드·배포 방식을 확인한다. 공식 저장소의 커밋을 고정해 재현 가능하게 한다. UI는 실제 Exact Contract/공식 웹 타깃으로 구현한다. Rust 기반 프레임워크라는 말을 모든 본문·브라우저 코드가 Rust여야 한다는 뜻으로 오해하지 않는다. 필요 로직은 Rust 우선, 웹 호스트 필수 도구는 공식 방식을 따른다. Exact 없이 기존 HTML만 새로 쓰고 Exact 구현이라고 주장하지 않는다.

ponytail full을 적용하되 본문·예제·접근성을 줄이지 않는다. 기존 frontend-design/rust-best-practices 스킬을 필요한 범위에서 적용한다. find-skills로 Exact에 필요한 스킬을 탐색하고 공식 배포 스킬이 있으면 우선 사용한다. 출처·내용을 검토한 뒤 필요한 것만 설치한다.
