## 학습 목표와 선수 개념

- 평균이 꼬리 지연을 숨기는 이유를 설명하고 p50·p95·p99를 계산한다.
- N+1 질의를 발견하고 JOIN으로 줄인다.
- 요청당 작업량을 비용으로 환산해 개선의 가치를 고객에게 설명한다.

선수 개념: 3.1절(JOIN), 5.1절.

## 현장 상황

고객사가 "평균 응답 140ms면 빠른데 왜 사용자들이 느리다고 하죠?"라고 묻는다. 동시에 클라우드 DB 비용이 지난달보다 크게 늘었다. FDE는 두 질문이 데이터로 답할 수 있는 질문인지 확인하고, 숫자로 설명해야 한다. 성능과 비용은 고객의 예산과 직결되므로 "빨라졌어요"가 아니라 "p99가 얼마에서 얼마로, 비용이 얼마에서 얼마로"라고 말할 수 있어야 한다.

## 원리와 용어

**백분위수(percentile)**: 값을 정렬했을 때 p%가 그 값 이하인 지점. p50(중앙값)은 보통 사용자의 경험, p95·p99는 느린 쪽 꼬리를 보여 준다. 이 책의 예제는 가장 가까운 순위(nearest-rank) 방식으로 계산한다. 계산 방식에 따라 작은 차이가 있으므로 비교할 때는 같은 방식을 쓴다.

**평균의 함정**: 지연 분포는 대개 한쪽으로 긴 꼬리를 가진다. 몇 건의 매우 느린 요청이 평균을 끌어올리면서, 동시에 대부분의 요청보다 평균이 커서 "평균보다 느린 요청은 소수"라는 이상한 결과가 된다. 사용자는 평균이 아니라 자기가 겪은 요청을 기억한다. 한 화면이 API를 10번 부르면 그중 하나가 p99에 걸릴 확률이 크게 늘어 꼬리가 화면 전체의 경험을 좌우한다.

**N+1 질의**: 목록 하나를 가져온 뒤(1번) 항목마다 관련 데이터를 한 번씩 더 묻는(N번) 패턴. ORM이 관계를 "필요할 때" 불러오는 기본 동작에서 흔히 생긴다. 개발 데이터 10건에서는 티가 안 나고, 운영 데이터 수천 건에서 지연과 DB 비용으로 드러난다. JOIN이나 `WHERE id IN (…)` 한 번으로 바꾼다.

**비용 환산**: 작업량 × 단가. 단가는 서비스와 계약에 따라 다르고 자주 바뀌므로 공식 가격표에서 확인한다. 이 절의 단가는 계산 방법을 보이기 위한 가정값이다.

- 비용은 같은 가정 단가에서 N+1이 JOIN의 51배다. 고객에게는 "질의 수를 문의 수와 무관한 1번으로 바꿔, 같은 트래픽에서 DB 질의를 98% 줄인다"처럼 단가와 무관한 비율도 함께 설명하면 단가가 바뀌어도 유효하다.

## 흔한 오류와 디버깅

- **추측으로 최적화**: 측정 없이 "아마 DB가 느릴 것"이라고 고치기 시작한다. 5.1절의 트레이스로 시간이 어디서 쓰이는지 먼저 본다.
- **개발 데이터로만 측정**: 데이터 양에 비례하는 문제는 작은 데이터에서 보이지 않는다. 운영 규모의 합성 데이터로 시험한다.
- **캐시로 덮기**: N+1을 캐시로 가리면 캐시가 비는 순간(배포 직후) 다시 터진다. 원인을 먼저 고친다.
- **백분위수 평균 내기**: 서버 10대의 p99를 평균하면 전체 p99가 아니다. 원자료나 히스토그램을 합쳐서 다시 계산한다.

## 이해 확인

::quiz
한 화면을 그리려면 서로 독립인 API 호출 5개가 모두 끝나야 한다. 각 호출이 1% 확률로 p99보다 느리다면, 화면 하나가 적어도 한 번 느린 호출을 기다릴 확률은 대략 얼마인가?
::answer
1 − 0.99⁵ ≈ 1 − 0.951 = 약 4.9%. 호출 하나의 1% 꼬리가 화면 단위에서는 약 5%로 커진다. 호출 수가 많을수록 꼬리 지연이 사용자 경험을 지배한다.
::end

::quiz
고객사 개발자가 "N+1이어도 질의 하나가 1ms라 괜찮다"고 한다. 어떤 정보를 더 확인해 판단하겠는가?
::answer
(1) N의 실제 크기: 운영에서 한 화면의 항목 수(50? 5,000?). (2) 질의당 지연이 네트워크 왕복을 포함한 값인지: 앱과 DB가 다른 서버면 왕복 지연이 질의마다 더해진다. (3) 동시 요청 수와 DB 연결 풀 크기: 질의가 많으면 연결을 오래 잡아 다른 요청이 기다린다. (4) DB 비용 구조: 질의 수나 사용 시간에 따라 과금되는지. 이 값들로 p95 지연과 월 비용을 계산해 보면 판단이 숫자로 바뀐다.
::end
