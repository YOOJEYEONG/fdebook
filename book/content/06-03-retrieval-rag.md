## 학습 목표와 선수 개념

- 검색 기반 생성(RAG)의 단계(색인 → 검색 → 프롬프트 구성 → 생성)를 설명한다.
- 텍스트를 벡터로 바꾸고 코사인 유사도로 가까운 문서를 찾는다.
- 임계값과 "모름" 경로로 근거 없는 답을 줄인다.

선수 개념: 6.1절. 벡터는 "숫자의 목록", 코사인 유사도는 "두 목록이 가리키는 방향이 얼마나 같은가(1이면 같은 방향, 0이면 무관)" 정도로 이해하면 된다.

## 현장 상황

고객사의 FAQ 문서 수백 개를 바탕으로 상담 답변 초안을 만드는 시스템을 만든다. 모델에게 그냥 물었더니 그럴듯하지만 고객사 정책과 다른 환불 기간을 답했다. 모델은 이 고객사의 내부 규정을 모른다. 해결책은 질문과 관련된 문서를 찾아 **근거로 함께 넣고**, 근거 안에서만 답하게 하는 것이다. Databricks AI FDE 공고는 RAG를 요구 역량으로 명시한다.

## 원리와 용어

**RAG(Retrieval-Augmented Generation)**: 생성 전에 외부 지식에서 관련 문서를 **검색**해 입력에 붙이는 방식. Lewis 등(2020)의 논문이 이 이름을 붙였다. 단계:

1. **색인**: 문서를 적당한 크기로 나누고(청크), 각 조각을 벡터로 바꿔 저장한다.
2. **검색**: 질문도 같은 방식으로 벡터로 바꾸고, 가장 가까운 조각 k개를 찾는다.
3. **프롬프트 구성**: 찾은 조각을 출처 id와 함께 넣고 "이 근거만 사용하라, 없으면 모른다고 하라"고 지시한다.
4. **생성과 확인**: 답의 문장마다 근거 id를 붙이게 하고, 근거에 없는 내용이 섞였는지 평가한다(6.4절).

**임베딩**: 의미가 비슷한 텍스트가 가까운 벡터가 되도록 학습된 모델이 만든 벡터. Claude 문서는 Anthropic이 자체 임베딩 모델을 제공하지 않고 Voyage AI를 안내하며, 질의와 문서에 서로 다른 `input_type`을 쓰는 방식을 설명한다. 이런 임베딩은 "환불"과 "돈 돌려받기"처럼 단어가 달라도 뜻이 비슷하면 가깝게 놓는다.

**이 절의 예제는 임베딩이 아니다**: 외부 API 없이 실행하기 위해 글자 2개씩 묶은 빈도(2-gram)로 벡터를 만든다. 같은 글자 조각을 공유해야만 가까워지는 **어휘 기반 검색**이다. 구조(벡터화 → 코사인 → 상위 k → 임계값)는 임베딩 검색과 같아서, `vectorize()`만 임베딩 모델 호출로 바꾸면 된다.

**임계값과 "모름"**: 가장 가까운 문서라도 충분히 가깝지 않으면 근거가 없는 것이다. 이때는 모델을 부르지 않고 상담원에게 넘기는 편이 틀린 답보다 낫다. 임계값은 감으로 정하지 않고 평가셋의 정답 문서로 조정한다.

## 예제: FAQ 검색과 프롬프트 구성

::example ch6/retrieval.py

해설:

- "환불은 언제 들어와요?"는 `환불`, `영업` 같은 조각을 공유해 faq-02를 찾았다. "주문 취소 가능한가요?"도 faq-04를 찾았다.
- "매장 영업시간"은 FAQ에 없는 질문이다. 최고 점수가 임계값보다 낮아 모델을 부르지 않고 상담원에게 넘긴다. 근거 없는 답을 원천 차단한다.
- "돈은 언제 돌려받나요?"는 **실패 사례**다. 뜻은 faq-02(환불)와 같지만 겹치는 글자 조각이 적어 점수가 낮다. 어휘 기반 검색의 한계이며, 의미 기반 임베딩이 필요한 이유다. 이런 질문을 평가셋에 넣어 두어야 검색 방식을 바꿨을 때 개선을 숫자로 확인할 수 있다.
- 마지막 출력은 실제로 모델에 보낼 프롬프트다. 문서를 `<doc id="…">`로 감싸 지시와 구분하고, 근거 id 인용과 "확인할 수 없습니다" 경로를 지시했다.

## 흔한 오류와 디버깅

- **청크가 너무 크거나 작음**: 너무 크면 관련 없는 내용이 섞이고, 너무 작으면 답에 필요한 맥락이 잘린다. 문단·제목 단위로 나누고 평가로 조정한다.
- **유사도 = 사실 정확성으로 착각**: 가까운 문서가 질문에 답하지 못할 수 있다. 검색 단계와 생성 단계를 따로 평가한다(검색: 정답 문서가 상위 k에 있었나 / 생성: 답이 근거와 일치하나).
- **문서 갱신 누락**: 정책이 바뀌었는데 색인을 다시 만들지 않으면 옛 정책으로 답한다. 3.4절의 증분 적재처럼 색인 갱신 파이프라인을 둔다.
- **검색 문서 속 지시문**: 검색된 문서는 신뢰할 수 없는 입력이다. 그 안의 "이전 지시를 무시하라" 같은 문장이 6.5절의 간접 인젝션이 된다.
- **권한 무시**: 사용자가 볼 수 없는 문서를 검색해 답에 넣으면 정보가 샌다. 검색 단계에서 문서 권한을 거른다(5.5절).

## 이해 확인

::quiz
평가해 보니 정답 문서가 검색 상위 2개 안에 든 비율은 95%인데, 최종 답의 정확도는 70%다. 어느 단계를 먼저 조사하는가?
::answer
검색은 대부분 성공하고 있으므로 생성 단계다. 근거가 있는데도 답이 틀린 사례를 모아, 프롬프트가 근거만 쓰도록 충분히 지시하는지, 여러 문서가 충돌할 때의 규칙이 있는지, 답이 근거를 왜곡하는지를 확인한다. 단계별 지표를 따로 재야 이런 판단이 가능하다.
::end

::quiz
예제의 임계값을 0.08에서 0.03으로 낮추면 "돈은 언제 돌려받나요?"도 faq-02를 찾는다. 그렇게 바꾸면 무엇이 나빠질 수 있는가?
::answer
"매장 영업시간" 같은 FAQ에 없는 질문(최고 0.046)도 임계값을 넘어 관련 없는 문서가 근거로 붙고, 모델이 그 문서로 엉뚱한 답을 만들 위험이 커진다. 임계값은 한 사례가 아니라 정답이 붙은 질문 전체(FAQ에 있는 질문과 없는 질문)로 재현율과 오답률을 함께 보며 정한다. 이 경우 근본 해결은 의미 기반 임베딩이다.
::end
