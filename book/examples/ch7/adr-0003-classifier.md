# ADR-0003: 문의 분류를 규칙 + LLM 2단계로 한다

- 상태: 승인됨 (2026-11-10). ADR-0001("규칙 기반 분류만 사용")을 대체한다.
- 결정한 사람: 고객사 운영팀장, 고객사 IT 리드, FDE
- 확신도: 중간. 파일럿 4주 데이터로 다시 검토한다.

## 맥락

- 월 3만 건의 문의를 4개 팀(배송, 환불, 계정, 기타)으로 배정한다. 오배정은 재배정 비용과 응답 지연을 만든다.
- 규칙 기반 분류(ADR-0001)는 배송·환불에서 정밀도가 높지만, 표현이 다양한 계정 문의 재현율이 0.55에 머물렀다.
- 고객 개인정보는 고객사 클라우드 계정 밖으로 나갈 수 없다(보안 검토 SEC-12).
- 상담원 2명이 분류 오류를 매일 수작업으로 고치고 있다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 규칙 개선만 | 비용 0, 설명 쉬움 | 계정 문의 표현 다양성을 따라가기 어려움(2주 시도에서 재현율 0.55 → 0.61) |
| B. 전부 LLM 분류 | 재현율 높음(평가셋 0.88) | 모든 건에 비용·지연, 개인정보 처리 경로 확대 |
| C. 규칙이 확실한 건만 처리, 나머지만 LLM | 비용을 B의 약 35%로 예상, 규칙의 정밀도 유지 | 두 경로를 운영·평가해야 함 |

## 결정

우리는 C를 택한다. 규칙의 확신 점수가 기준 이상인 문의는 규칙으로 배정하고, 나머지만 고객사 계정 안의 LLM 엔드포인트로 분류한다. LLM 결과는 스키마 검증(6.1절)을 통과하지 못하면 사람 검토 대기열로 보낸다.

## 결과(트레이드오프)

- 좋아지는 점: 계정 문의 재현율 개선 기대, 비용은 B보다 낮음.
- 나빠지는 점: 분류 경로가 둘이라 평가와 모니터링을 각각 해야 한다. 규칙 기준값 조정이 새 운영 업무가 된다.
- 위험: LLM 엔드포인트 장애 시 해당 문의는 사람 검토로 간다(처리 지연). 경보 기준을 런북에 둔다.
- 다시 볼 조건: 파일럿 4주 후 계정 재현율이 0.8 미만이거나 월 비용이 예산을 넘으면 이 결정을 재검토하고 새 ADR로 대체한다.
