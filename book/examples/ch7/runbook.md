# 런북: 문의 자동 분류 서비스

담당: 고객사 IT 운영팀 (1차), 고객사 IT 리드 (2차). 최종 갱신: 2026-11-17.

## 서비스 개요
- 하는 일: 새 문의를 받아 팀(배송·환불·계정·기타)과 긴급도를 정해 상담 시스템에 기록한다.
- 구성: 웹훅 수신 API → SQLite/DB 저장 → 분류(규칙 → 필요 시 LLM) → 상담 시스템 API로 배정.
- 의존: 상담 시스템 API, 고객사 계정의 LLM 엔드포인트.
- 설정: 환경 변수 `APP_ENV`, `DATABASE_URL`, `WEBHOOK_SECRET`, `LLM_ENDPOINT`(값은 비밀 저장소. 이 문서에 쓰지 않는다).

## 정상 상태 확인
1. 대시보드 "classifier": 5xx 비율 < 1%, 분류 지연 p95 < 5초, 사람 검토 대기열 < 50건.
2. `GET /health`가 200이고 본문의 `db`, `llm`이 모두 `ok`.

## 경보별 대응
| 경보 | 먼저 할 일 | 그래도 안 되면 |
|---|---|---|
| 웹훅 5xx > 2% (5분) | 직전 배포가 있으면 롤백(아래 절차) | 2차 담당 호출, 상담 시스템 공급사 상태 페이지 확인 |
| LLM 오류율 > 10% | 분류가 자동으로 사람 검토로 넘어가는지 대기열 증가 확인 | 상담팀장에게 수작업 배정 인원 요청 |
| 사람 검토 대기열 > 200 | 원인 경로(규칙/LLM/검증 실패) 지표 확인 | 검증 실패 급증이면 최근 프롬프트·스키마 변경 되돌림 |
| 긴급 문의 30분 미배정 | 상담팀장에게 즉시 전화 | 사후 검토 대상 |

## 롤백 절차
1. 배포 기록에서 직전 이미지 태그(커밋 SHA)를 확인한다.
2. `deploy --image classifier:<직전 SHA>`로 배포한다(스테이징에서 분기마다 1회 연습).
3. 5xx 비율과 대기열이 10분 안에 정상으로 돌아오는지 본다.
4. 장애 채널에 시각과 조치를 기록한다(사후 검토 자료).

## 정기 작업
- 매주 월요일: 평가셋 자동 실행 결과 확인(클래스별 재현율 0.7 미만이면 FDE/개발팀 티켓).
- 매월: 웹훅 비밀값과 LLM 자격 증명 교체 일정 확인.

## 하지 말 것
- 운영 DB에서 직접 `UPDATE`로 분류를 고치지 않는다(감사 기록이 남지 않음). 관리 API를 쓴다.
- 로그에 요청 본문 전체를 켜지 않는다(개인정보).
